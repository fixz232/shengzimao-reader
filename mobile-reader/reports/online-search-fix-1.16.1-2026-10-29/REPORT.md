# 1.16.1 在线搜书修复

日期：2026-10-29。版本：1.16.1 / 27。正式包名：`com.shengzimao.reader.mobile`。

本轮实现上一轮审查中的四项修复，保留在线听书、聚合分组、用户书源、番茄小说及现有小说／漫画功能。没有连接、安装或操作手机，没有推送 GitHub。

## 四项修复

1. **目录与正文分页完整性。** 分页身份包含网址、请求方法、正文参数、字符集及显式分页请求头，不再把同 URL 的不同 POST 页混为一页。身份摘要按请求缓存，避免队列去重反复序列化大请求头。公共动态鉴权请求头不改变逻辑页面身份；响应重定向别名仍参与去重。相邻章节和目录边界也保留完整请求参数，不只比较裸 URL。继续保留 100 页目录、50 页正文、章数及正文长度上限。
2. **下载不阻塞阅读。** 下载、搜索和书源管理继续串行保护旧引擎全局状态；阅读使用另一把锁。SoNovel 阅读独立复用一个类加载器与工作目录，下载的 `configure`、全局上下文、正文输出不再与阅读实例共用。引擎初始化串行保护进程配置属性和资源释放。导入规则后失效相关阅读实例；Legado 规则缓存增加同步保护。结果卡在后台下载期间可继续点“阅读”或“加入书架”。
3. **搜索筛选恢复。** 新搜索 revision 自动清除上一次结果来源筛选；筛选后为空时提供明确提示和“查看全部书源”入口。
4. **失败原因与独立重试。** 聚合搜索保留成功结果，展示失败来源和具体原因；支持只重试失败源并合并结果，不重复请求成功源、不覆盖用户保存的搜索范围。重试中保留尚未完成来源原来的失败记录，取消后仍可继续重试。SoNovel 完成事件携带来源及失败原因；整体引擎异常会补齐未完成源的失败状态与进度。

实际故障回归还确认 SoNovel 在自己的 `SearchParser` 内部吞掉请求／解析异常。构建期在两个既有异常处理器中记录线程局部错误，包装器按源读取并清除，恢复既有返回行为，同时不再把失败误报成普通无结果。构建工具要求匹配两个处理器，否则直接失败，不静默生成缺少适配的包。

## 验证证据

- 新增 `NovelPaginationRegressionTest` 九项用例：同地址 POST 目录与真实回环、同地址 POST 正文与相邻章边界、请求头分页、JSON 键顺序、请求身份规范化、动态默认请求头、鉴权头循环保护、未请求页面不执行鉴权脚本和重定向别名回环。
- `engine/tests/StreamingSearchSmoke.java` 使用实际重建后的 Java 包装器及核心，在本机 HTTP 回环源验证五组行为：关键词编码；单源隔离与首批即时展示；快慢源并行及失败来源显示；仅失败源重试恢复；下载阻塞时另一阅读会话可完成正文请求，下载目录与正文保持隔离。
- 故障源通过主动关闭本机 HTTP 连接注入真实请求错误，不以普通空结果冒充失败。
- 最终构建、完整单元测试、Release Lint、签名、对齐及 APK 内容检查结果以本目录日志和 JSON 清单为准；仅将通过最终检查的产物复制到 `dist`。

## 范围

本机回环与 JVM 回归不等于 Android 真机全功能验收。本轮没有逐个访问所有第三方书源，站点停服、网络限制、登录验证和规则变化仍可能影响阅读；不能用构建成功承诺所有设备与所有书源永远没有问题。

修复作用于后续的目录和正文获取。若旧版已经保存了不完整的在线目录或正文，可用阅读页的目录刷新和强制重读重新获取；已经生成的不完整离线文件需要重新下载。
